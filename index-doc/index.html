Chế độ hoạt động

Offline cục bộ & Online 3 miền

Online · Live Multi-Region

Online 3 miền

  • Internet liên tục (4G/Wi-Fi) tại mọi điểm cầu
  • Nút GỬI ĐIỂM → Fetch POST → Apps Script → Sheets ngay
  • Dashboard & Scoreboard cập nhật realtime
  • Hạ tầng video Meet / Zoom / Teams (kịch bản Live)

Đồng bộ ngay khi gửi điểm — hậu kỳ chủ yếu xuất PDF và lưu Drive.

Offline · LAN Local Server

Offline cục bộ · Phương án B

  • Router Wi-Fi LAN nội bộ — không cần Internet khi thi
  • Laptop Thư ký host Local Server tại http://192.168.1.100:3000
  • Nút GỬI ĐIỂM → POST Local API → SQLite — realtime
  • Phương án A: Hotspot 4G → hoạt động gần như Online (dự phòng)
  • Phương án B: LAN Local Server — Dashboard & Scoreboard realtime tại sân

Sau thi: ĐỒNG BỘ / POST /api/sync/push đẩy dữ liệu từ Local Server lên Google Sheets & Drive.

Import toàn bộ danh sách võ sinh đủ điều kiện dự thi vào hệ thống trên Google Sheets.

  • Danh sách này là nguồn dữ liệu nền để giám khảo chấm điểm
  • Giúp đồng bộ tên võ sinh, CLB/đơn vị và dữ liệu hiển thị sau này
  • Cần hoàn tất trước khi sinh QR/link cho giám khảo

Hệ thống sinh sẵn đường dẫn hoặc mã QR truy cập Web App chấm thi cho giám khảo.

  • Giám khảo dùng điện thoại / tablet quét QR link LAN (http://192.168.1.100:3000) hoặc Online (GitHub Pages)
  • Nếu dùng Phương án B — LAN Local Server: link/QR trỏ tới IP nội bộ, ví dụ http://192.168.1.100:3000
  • Nếu dùng Cloud-First / Online: link trỏ tới Web App trên GitHub Pages

Bước này bắt buộc khi vận hành Phương án B — LAN Local Server tại sân thi.

  • Cài & khởi động Local Server trên laptop Thư ký (npm start · IP tĩnh 192.168.1.100:3000)
  • Snapshot dữ liệu kỳ thi: POST /api/sync/pull (Sheets → SQLite)
  • Cấu hình Wi-Fi router, ví dụ SSID PQQ_KhaoThi
  • Kiểm tra máy in USB gắn laptop Thư ký
  • Test end-to-end tại nhà: gửi điểm mẫu → Scoreboard cập nhật trong 3–5 giây

Vấn đề thực tế cần tránh

  • Setup mạng LAN ngay tại sân thi có rủi ro cao: máy không nhận IP, đứt cáp, sai cấu hình.
  • Không lưu điểm rời rạc trên từng điện thoại — dùng Local Server làm điểm tập trung cho Scoreboard realtime.
  • Các thiết bị bắt buộc phải “nói chuyện” được với nhau nếu muốn hiển thị Thủ khoa thời gian thực.

Kịch bản 1 · Online 3 miền

  1. Giám khảo nhập điểm và nhấn GỬI ĐIỂM
  2. Apps Script validate payload JSON, ghi Google Sheets ở trạng thái DRAFT
  3. Thư ký rà soát, nhấn Khóa phiếu → PENDING_APPROVAL
  4. CCK nhập PIN, Apps Script xác thực hash PIN + role → OFFICIALLY_APPROVED

Kịch bản 2 · Offline cục bộ (LAN Local Server)

  1. Thư ký bật router + Local Server trên laptop (192.168.1.100:3000)
  2. Giám khảo kết nối Wi-Fi LAN, nhập điểm và nhấn GỬI ĐIỂM
  3. Local API ghi SQLite → Dashboard & Scoreboard polling realtime (3–5 giây)
  4. Thư ký khóa phiếu → CCK PIN → sau thi: ĐỒNG BỘ lên Cloud

Khóa phiếu ở Frontend + Backend

Khi Thư ký khóa phiếu, UI sẽ disable input và nút gửi; Backend vẫn bắt buộc chặn mọi request sửa điểm nếu phiếu không còn ở trạng thái DRAFT.

PIN không lưu plaintext

Apps Script nên xác thực bằng hash PIN + salt, ràng buộc role CCK và giới hạn số lần thử sai để bảo vệ bước duyệt chính thức.

Xử lý sự cố

Idempotency, LAN Sync và Conflict Resolution

Online · mạng chập chờn

Idempotency Key

Mỗi lần submit giữ nguyên idempotencyKey cho cùng một scoreKey. Nếu người dùng bấm nhiều lần hoặc request timeout, Apps Script chỉ trả lại kết quả cũ thay vì ghi thêm dòng mới.

Offline · xung đột đồng bộ

Conflict Resolution

Nếu cùng một scoreKey nhưng khác payloadHash, hệ thống không overwrite trực tiếp mà đánh dấu NEEDS_REVIEW, chờ CCK đối chiếu video và chọn attempt đúng trước khi duyệt chính thức.

Kiến trúc LAN tại sân

  1. Laptop Thư ký host PWA + Local API + SQLite tại :3000
  2. Router Wi-Fi PQQ_KhaoThi — không cần Internet
  3. Giám khảo truy cập http://192.168.1.100:3000
  4. Frontend adapter: cùng payload, đổi API_BASE theo hostname
  5. Sau thi: sync/push SQLite → Google Sheets & Drive
